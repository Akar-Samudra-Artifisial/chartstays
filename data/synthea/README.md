# Synthea subset

Synthetic patients only. No real person's data is stored in this repository.

- Source: `synthea_sample_data_fhir_latest.zip` from
  [synthetichealth/synthea-sample-data](https://github.com/synthetichealth/synthea-sample-data)
  (FHIR R4, 112 patients), repository commit `84f59805d481b9f01f3141ef39e68bdbbeb80132`
  (2026-10-21), archive SHA-256
  `66141b772671452f590f9b7bb999eb201f1f16beb94a84ab0885ed723b36b315`.
- Generated by [Synthea](https://github.com/synthetichealth/synthea) (Apache License 2.0).
  The sample-data repository declares no license of its own.
- Built with `node tools/synthea-subset.mjs <extracted-folder>`; the archive itself is not
  committed.

## Contents

- `patients/*.json`: 8 patients chosen to cover the four disease areas, trimmed to the
  resource types the matcher reads (Patient, Condition, Observation, MedicationRequest).
  `patients/index.json` says why each one was kept.
- `shifted/*.json`: the same bundles with every date moved by one offset per patient so the
  latest record date is 2026-11-01 (`pnpm synthea:timeshift`; synthetic records, dates
  shifted so the latest encounter is recent; standard practice for synthetic demo data).
  `shifted/index.json` lists each offset. The report, golden test and demo use these.
- `code-inventory.json`: every Condition (SNOMED CT), Observation (LOINC) and
  MedicationRequest (RxNorm) code in the **whole** 112-patient sample, with patient counts.
  `pnpm validate` fails when a curated criterion uses a code that is not in this file.
